# EvoCoup

![EvoCoup — a Renaissance court of rivals](images/cover.png)

EvoCoup is a local web game and AI sandbox for playing faithful games of [Coup](https://www.ultraboardgames.com/coup/game-rules.php) against large language models—or watching a table of models play against one another.

The project began as an experiment in evolving recurrent neural networks. Its new direction replaces that idea with LLM-controlled players, a rigorously tested rules engine, and an animated browser interface. The EvoCoup name is retained for now and may change later.

> **Status:** the redevelopment is currently in the planning stage. The repository still contains the original random-play Python prototype; the new rules engine, OpenAI integration, and web application have not been implemented yet. See [PLAN.md](PLAN.md) for the implementation-ready specification.

## The game

Coup is a bluffing and deduction card game. Each player begins with two hidden character cards representing their influence at court. On a turn, a player may take an ordinary action or claim a character's power—whether or not they actually hold that character. Other players can challenge the claim or counteract the action with claims of their own. The last player with influence remaining wins.

EvoCoup will implement the published base rules for two through six players, including the published two-player variant.

## V1 goals

- Play locally as one human against one to five OpenAI-controlled opponents.
- Watch games containing two to six OpenAI-controlled players.
- Enforce all rules in a deterministic, independently tested Python engine.
- Make every AI action, challenge, block, reveal, and exchange choice through a genuine model decision.
- Give each agent only its own hidden cards and the public history of the match.
- Animate the table in a React and TypeScript frontend backed by FastAPI and WebSockets.
- Support pause, step, normal-speed, accelerated, and instant AI-only play.
- Provide an optional developer panel showing model inputs, legal choices, decisions, concise rationales, latency, token usage, and errors.
- Stop safely on OpenAI API failures and allow the failed decision to be retried without substituting a fallback move.

V1 will run entirely on a laptop with an OpenAI API key. It will not require accounts, deployment, a database, or saved games.

## Architecture

The planned implementation separates four concerns:

1. **Rules engine** — a pure Python state machine that owns legal moves, hidden information, randomness, challenges, counteractions, and victory.
2. **Match runner** — coordinates human and AI decision providers without duplicating game rules.
3. **OpenAI adapter** — sends a private seat-specific view and engine-generated legal choices to the Responses API, then validates one structured decision.
4. **Web application** — a FastAPI/WebSocket backend and animated React/TypeScript table.

The model will never mutate game state directly. It chooses from options generated by the rules engine, and the engine validates every response before applying it.

## Current prototype

[`coup.py`](coup.py) is the original command-line simulator. It randomly chooses actions and responses to exercise an early implementation of the game loop. It does not contain an RNN, evolutionary training, LLM integration, or the new rules architecture, and it has known rule-resolution defects. It will be retained as historical context rather than extended into the new application.

## Future directions

After v1, possible additions include table dialogue and negotiation, distinct agent personalities, per-seat models, multiple model providers, persistent match replays, batch tournaments and win-rate analysis, final artwork, and sound. Evolutionary learning is no longer a project goal.
